SYSTEM SPECIFICATION & ARCHITECTURE
Data Warehouse Solution for Online Furniture Retailer
(Online Möbelhandel)
End-to-End Implementation of an Operational Business DB, Dimensional Star Schema, and ETL Pipeline

1. MOTIVATION & BACKGROUND

A German online furniture retailer (comparable to home24) sells furniture and home accessories to private customers throughout Germany. The operational shop database is designed exclusively for processing individual transactional orders answering "what is in order 41725?" quickly. However, it cannot efficiently answer high-level analytical queries such as "how did revenue per product category develop over the last two years?" without executing expensive joins and aggregations across the live transactional system.

This project builds a compact yet complete data warehouse solution for the retailer: a normalized operational source database, a dimensional target model, and a Python-based ETL process connecting the two systems.

2. PROJECT OBJECTIVES

1. Operational Source (Business DB)

Design and implement a relational database in 3NF representing the shop's order-taking process.

2. Target Data Warehouse

Design a Star Schema dimensional model and implement an automated ETL pipeline in Python to transform and load transactional data.

3. Slowly Changing Dimensions (SCD)

Analyze dimension attribute behavior and demonstrate precise handling of SCD Types 0, 1, and 2.

4. Business Intelligence & Analytics

Formulate and execute analytical SQL queries against the warehouse to deliver key operational insights.

4. CORE ANALYTICAL QUESTIONS

The dimensional warehouse is specifically designed to evaluate two core business queries alongside supplemental extensions:

Q1
Revenue and Discount by category over time		 How does net revenue as well as Discounts develop per top-level product category and Quarter? DIM_Date, DIM_Product
Q2
Top 10 PLZ zones by net revenue		 Which 10 postal code zones (first 2 digits of PLZ) generate the maximum net revenue? DIM_Customer
Q3
Top 2 categories per federal state		 What are the two highest net revenue generating product categories per federal state? DIM_Customer, DIM_Product
Q4
Peak order volume by weekday		 Which weekdays see the highest order volume across the two-year period? DIM_Date
Q5
Peak calendar weeks (Top 10)		 Which calendar weeks see the highest order volume? DIM_Date
Q6
Revenue by price segment		 How does revenue compare across Budget / Mid-range / Premium product segments? DIM_Product
Q7
Federal state revenue growth		 Which federal states show the strongest revenue growth from 2024 to 2025? DIM_Customer, DIM_Date
Q8
Top 3 suppliers per quarter		 Which 3 suppliers generate the most net revenue per Quarter? DIM_Supplier, DIM_Date
Q9
Supplier Discount behaviour		 Which suppliers' products carry the highest average Discount rate, and does that correlate with order volume? DIM_Supplier

5. TARGET WAREHOUSE SCHEMA

A star schema layout where the grain of the fact table is one row per order line.

Figure 1.1 — mER-Diagram: Data Warehouse
Figure 1.2 — Star Schema: Data Warehouse
Table Role Content & Transformations
FACT_Sales Fact Table Quantity, GrossAmount, DiscountAmount, NetAmount, ShippingCost. Uses OrderId as a degenerate dimension. (~85,500 rows)
DIM_Date Dimension (SCD 0) Day, month, month name, quarter, year, weekday, calendar week. Derived from order date boundaries. (731 rows)
DIM_Customer Dimension (SCD 2) Name, address, postal code, city, state, plus derived PlzRegion (1 digit) and PlzZone (2 digits). Tracks history with ValidFrom, ValidTo, IsCurrent. (5,000 rows)
DIM_Product Dimension (SCD 1) Product name, colour, material, list price. Category hierarchy is flattened into top-level and sub-categories. Overwrites changes. (120 rows)
DIM_Supplier Dimension (SCD 0) Supplier name, city, country. Immutable baseline reference. (20 rows)

6. ETL PROCESS & TRANSFORMATION LOGIC

A 3-stage Python ETL pipeline extracts data from the Business DB, executes transformations, and loads the target star schema:

  • Surrogate Keys: Sequence-based primary keys (*Sk) for all dimensions, completely decoupled from source keys (*Id).
  • Hierarchy Flattening: Unrolls two-level normalized category hierarchies directly into DIM_Product.
  • Measure Calculations: Pre-computes GrossAmount, DiscountAmount, and NetAmount per fact row.
  • Idempotent Execution: Executed via staged scripts (RAW_ staging → FULL_ staging → DWH tables).
